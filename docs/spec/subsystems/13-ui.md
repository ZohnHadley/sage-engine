# 13 · Game UI

> Status: toolkit built and tested, player-facing menu set partly built. Fonts, options screens, rebinding and accessibility are not started. Owning assemblies: `Sage.UI` (plugin `sage.ui`), `Sage.Simulation` (legacy panels), `Sage.Client` (drawing), `Sage.Editor` (ImGui dev tools). Design doc: [13-ui](../../design/13-ui.md).

## 1. Purpose and scope

The game UI shows simulation state to the player and turns input into commands: HUD, menus, inventory, loot, dialogue topics, journal, map, shop. It is our own retained toolkit, not a third-party library, so that layouts, styles and text are content a designer or modder can edit, and a running game follows the edit.

It deliberately does not do the following. Developer tools (console, stat overlays, the editor) are Dear ImGui and live in `Sage.Editor`, never in a Shipping build. Genre screens (inventory grid, shop, spellmaker) are the RPG kit's, see [17-rpg-kit](17-rpg-kit.md). The UI reads simulation state and never writes it; a button that changes the game sends a command or calls a rule. Device polling and the mapping of keys to actions belong to [12-input](12-input.md); the text drawing primitives belong to [07-rendering](07-rendering.md).

## 2. Responsibilities

- Retained widgets and a two-pass layout in virtual units, headless, with hit testing.
- Style records with state colours, nine-sliced images and inheritance through `base`.
- Layout records as flat named node trees, patchable per node by a mod.
- Property binding from a view-model to widgets, with conditions (`visibleIf`, `enabledIf`).
- Focus, tab order, spatial gamepad navigation, pointer hover and click, tooltips.
- Localisation: string tables, `@ns.key` references, placeholders and plural forms.
- A screen stack with modal and non-modal layers, open and close transitions, and a HUD layer.
- A render plan that the client replays, and the client `WidgetRenderer`.
- Hot reload of styles, layouts and strings.

Not responsible for: fonts and glyph rasterisation beyond the built-in bitmap font (open, #338), the rebinding itself (`InputRebinds`, [12-input](12-input.md); the screen over it, `ui_controls`, is here), save-slot logic (see [15-saves](15-saves.md)), or the content of any RPG screen.

## 3. Placement and dependencies

`Sage.UI` is a base assembly on the simulation: `Sage.Simulation` ← `Sage.UI` ← `Sage.Client`. It references the simulation for `Rect`, conditions and records, and nothing of physics or gameplay. It is simulation-only (no MonoGame, SAGE0024) and not a kit (SAGE0025). Its public API is declared and marked experimental (SAGE0125). The plugin `sage.ui` (`UiModule`, in `BasePlugins.All`) owns three records and the `view_model` vocabulary. A kit that needs it brings it in without game.json naming it.

The legacy panel path (`Panel`, `PanelRow`, `PanelLayout`, `Screen`, `ScreenStack`, `TextField`) lives in `src/Sage.Simulation/UI`. Drawing lives only in `Sage.Client` (`UiDraw`, `UiRenderSystem`, `ScreenSystem`, `WidgetRenderer`). ImGui lives in `Sage.Editor` and `Sage.Editing`'s models are headless.

## 5. Data model

| Record | Declared in | Purpose |
|---|---|---|
| `ui_style` | `UiRecords.cs` | Font name, `textScale`, `padding`, `borderWidth`, colours (`textColour`, `background`, `border`, `fill`, `tint`), `image` and `slice`, and `states` (`hover`, `focused`, `pressed`, `disabled`). |
| `ui_layout` | `UiRecords.cs` | A style and `nodes`: a flat tree by name, each with `widget`, `parent`, `order` and the widget's fields, `bind`, `bindings`, `args`, `visibleIf`, `enabledIf`. |
| `screen` | `UiRecords.cs` | A `layout`, a `viewModel` id and `sounds` (a `ui_sounds` set of its own). |
| `ui_sounds` | `UiRecords.cs` | `move`, `select`, `open`, `close`, each a `sound`; `sage:default_ui_sounds` is the game's default (every field empty = silent) and a screen's own set wins field by field (#330). `move` is raised on navigation input only, not on hover or initial focus; HUD layers and `CloseAll` are silent. Tests: ScreensRaiseTheirSoundsForOpenMoveSelectAndClose, AScreenNamesItsOwnSoundsAndFallsBackToTheDefaultForTheRest. |

A node's anchors accept names (`"bottom_right"`, `"fill"`) or four fractions. Margins and padding accept `4`, `[h, v]` or `[l, t, r, b]`. Strings are JSON tables under `strings/<lang>/` with plural forms; `@ns.key` in any layout text is resolved at build. No component or saved resource is owned here; the map marker component belongs to the RPG kit. `sage schema` writes schemas for all three records, with the widget types, style ids and view-model ids as enums.

## 6. Lifecycle and data flow

`UiModule.Init` registers cvars and commands and provides `Localisation`, `UiStyles` and `UiScreens`. Records are read at load, where mistakes are errors at their lines.

Per frame, `ScreenSystem` (`sage.client.screens`, Phase.Overlay) fills `UiInput` from the `ui` context and the mouse, calls `UiScreenStack.Update` for the top modal layer, refreshes every open view-model, and advances transitions by real frame time (clamped to 0.1 s), so menus run while the game is paused. `UiRenderSystem` (`sage.client.ui`, Phase.Overlay, after screens) draws the immediate-mode queue, the crosshair and then the widget plans. A plan is rebuilt only when the root version, style version, localisation version, pressed widget or viewport changes; the client applies fade, slide and focus easing as it replays.

The HUD is a screen record on a non-modal layer (`OpenHud`): drawn under windows, never the stack's `Top`, never closed by Back. The legacy path (`Screen`, `ScreenStack`, `Panel`) still hosts the kit's dialogue, journal and spellmaker panels and the first-person hands; a widget screen draws over them and takes input while open. Immediate-mode drawing (`UiDraw` rectangles, text, images) remains for the crosshair, damage numbers and hands.

A save slot menu reads `SaveSystem.Slots`; a load runs inside the stack update after the frame's ticks, which is the tick boundary a save needs. UI state is not saved.

## 7. Threading, memory and performance

All UI work runs on the main thread. Layout, binding refresh, navigation, hover, scroll, render-plan upkeep and HUD frames allocate nothing in steady state; reflection runs once per (type, path) and compiles to a delegate returning a `UiValue` struct. A clean tree answers layout from cache.

Tests: `LayingOutAndUpdatingACleanTreeAllocatesNothing`, `AnOpenScreenIsHostedAndPlannedWithoutAllocating`, `TheHudIsAScreenRecordAndAFrameOfItAllocatesNothing`, `RefreshingTheRpgScreensAllocatesNothing`. Rows that come and go are pooled and reused.

## 8. Errors and diagnostics

Layout and screen mistakes are load errors at the file and line, with the nearest valid name: unknown widget type, bad parent, parent loop, a scroll with several children, unknown binding, a missing view-model or a bound path its type lacks (test: `LayoutMistakesAreErrorsAtTheirLines`). A missing string key shows the key and warns once (test: `AMissingKeyShowsTheKeyItselfAndWarnsOnce`); in a dev build and in `sage validate` every `@key` no table has is a warning at its line. An unknown style id falls back to the default and warns once. Debug with `ui_open` and `ui_close`. Hot reload of records, `strings/` and the `lang` cvar rebuilds open screens in place (test: `ChangingARecordReLaysOutAnOpenScreen`).
