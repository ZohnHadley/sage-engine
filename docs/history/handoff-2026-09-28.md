## 2. How Phase 2 was built (and how to keep building it)

- **Parallel agents in git worktrees.** Each sub-issue went to an agent working in its own worktree
  (`git worktree add -b <branch> /tmp/.../wt-x origin/main`) on its own branch, with its own diagnostic id
  range (SAGE0020s, 0030s, 0040s) so they couldn't collide. The lead reviewed each branch, merged `main`
  into it, re-ran everything, opened the PR and merged it on green. Remove worktrees when done
  (`git worktree remove`).
- **Merge conflicts between agents were mostly docs and counts**, except where two designs met: #58's
  `RecordRef<T>` and #18's `[RecordRef("x")]` attribute were reconciled in #59 (fields are `RecordRef<T>`,
  the attribute stays for plain `RecordId` fields, and the metadata reads the target from either).
- **Generators and analyzers live in one project**, `src/Sage.Generators` (netstandard2.0, Roslyn 4.8),
  taken as an analyzer by every `src/` and `games/` project. Tests drive them with
  `CSharpGeneratorDriver` / `CompilationWithAnalyzers` (see `DeclarationTests`, `AnalyzerTests`).
  To read generated code: build with `--no-incremental -p:EmitCompilerGeneratedFiles=true
  -p:CompilerGeneratedFilesOutputPath=<dir>`.

## 5. Traps this session hit

- **`check_docs` found names with regexes**, so when `[Record("x")]` gained a `Plugin =` argument it
  silently counted 1 record type instead of 25 — and `--fix` wrote that into three docs. It now reads the
  registry dump (#18), which is the fix; the lesson is to distrust a count that suddenly drops.
- **Allocation measurements are per thread.** Bepu hands work to free threads, so a 40-byte allocation
  moves between runs under load. Measure with slack below one-object-per-tick, or not at all.
- **A green PR was tested against the `main` it branched from.** With several agents landing in one hour,
  merge `main` into each branch and re-run everything before merging it; it caught real conflicts every time.
- **Content changes are errors now.** Old C# names in prefabs (`"AIState"`), `"Wait:1.5"` tasks, unknown
  fields and wrong-type references stop a load with file:line — which is the point, but it means a
  content edit is checked as strictly as code. `sage validate` says the same headless.
- **Windows writes `\r\n`.** `StringBuilder.AppendLine` follows the platform, so the FGD differed on
  Windows and a test matching `\n` failed there only (#59). Generated text uses `\n` everywhere now; a
  test over generated text should say so (`Assert.DoesNotContain("\r", …)`).
- **The log is asynchronous and process-wide.** A sink added mid-test also receives whatever was still
  queued, including what an earlier test logged on the same xUnit thread — which is how a warning from a
  system test turned up in `sage validate`'s report in CI (#59). `Log.Flush()` before `Log.AddSink`.
- **The generator runs in every `src/` and `games/` project but not in tests**: test assemblies are read
  by reflection. A test type with `[Record]` must be registered by hand (`OnRegistered`).
