## 2. Done: #24, the assembly split

- **Merged from branch `claude/p3-assembly-split`** in four commits (decouple; split with the namespace
  still `sage_engine`; rename to `Sage.*`; SAGE0025, guards and docs). Plan:
  [`plan-24-assembly-split.md`](plan-24-assembly-split.md); what differs from it is in REDESIGN §3.1
  "As built".
- **Shape:** `Sage.Core ← Sage.Simulation ← Sage.Physics3D ← Sage.Gameplay`; `Sage.Client → Gameplay`.
  `Engine`, `World` and `SageApp` sit in Simulation (`World` and `IModule.OnWorldCreated(World)` make them
  inseparable). `SageAppOptions.AvailablePlugins = BasePlugins.All()` replaces `IncludeSimulationModules`.
  Games reference all four base assemblies through `games/Directory.Build.props`.
- **Guards:** SAGE0025 (a base assembly, `SageBaseAssembly=true`, references a `Sage.Kits.*` assembly);
  `SageSimulationOnly` is on by default for `src/` (Client, Editor, Host opt out);
  `AssemblyLayeringTests`; `EngineAssemblies.Base` in Sage.Testing (use it, not `typeof(Engine).Assembly`,
  when a test scans the engine). `src/Sage.Generators/SageTypes.cs` holds the type names the generators use.
- **Baseline held after every commit:** registry dump (only `assembly` changed), `sage validate`,
  `sage schema` (byte-identical), the ECS schema counts, the smoke runs. Tests: 702.
- **Left for later issues:** #25 (Friflo types still named directly), #27 (RPG screens parked in
  `Sage.Gameplay/Rpg/`; the client still makes the dialogue screen), #30 (Gameplay still references
  Physics3D; `IPhysicsWorld` is a seed), #31 (internals made public in the split: decide which stay).

**Deviations worth knowing:** Sage's `IComponent`/`ITag` extend Friflo's (zero-cost; Friflo's schema scan
needs it), so games still *reference* Friflo at compile time but may not *name* it (SAGE0050).
`AIProfile` became `AiProfile`. Actions are still registered in code; the conventions record picks among
them. `GameRules.OnWorldStarted` now spawns the scene's player by default.

**Follow-ups found this round** (small; file or fold into the next issues):
- Content using a disabled plugin's parts (`faction`, `dialogue`) still fails to load.
- Engine render/physics defaults (`lit_default`, `clear` weather, `default` physics material) are still
  `sage:` constants in Simulation.
- The scene record has no conventions slot yet (`[RecordRef("gameplay_conventions")]`); no time-of-day.
- Saves don't record a world's scene; the editor flattens a placement's own `relativeTo` on save.
- Depenetration and pushing (TODO 61); physics sync/write-back to the shared layer for a 2D backend;
  contacts are per-tick lists, not bus events.
- #31: which newly public members stay public (`Entity.DeleteEntity`/`AddChild`, the internals #24 opened);
  the Shipping dummy in `World.Get<T>`.
- Gameplay → Physics3D reference goes once a composition root exists (#32).
