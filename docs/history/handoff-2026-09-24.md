# Handoff — 2026-09-24

Written at the end of the session that finished R6, F14, R18 and F4. It is for whoever picks the engine
up next, with no memory of how it got here: where it stands, how to prove that for yourself, what to do
next, and the specific traps this engine has already sprung on somebody.

---

## 1. Where it stands

`sage-engine` is a C#/MonoGame engine for a **Daggerfall-like** first-person RPG, with an HL1-like, a
Lugaru-like and a Warband-like named as later targets. Multiplayer is deliberately **not** built;
["readiness rules"](../../ARCHITECTURE.md) keep the option open. Modding is **data + trusted C# mods**.

The vertical slice is walkable, fightable, lootable, castable, resumable, unbounded and audible:

| | |
|---|---|
| Console commands | 76 |
| Record types | 18 (`ability`, `attack`, `attribute`, `cue`, `damage_type`, `effect`, `item`, `material`, `prefab`, `sound`, `sprite_sheet`, `tag`, …) |
| Headless tests | 405, green in Debug and Development (see §3 for why Shipping is not a test configuration) |
| Phases | 13 — Fixed: Commands, PrePhysics, Physics, PostPhysics, Gameplay, AI, Animation, EntityIO, Late; Frame: FrameUpdate, Extract, Render, Overlay |
| Steady-state allocation | 40 bytes a tick with 2,000 entities and 100 thinking creatures ([the numbers](scale-2026-09-24.md)) |

What that means concretely: you spawn in a streamed, unbounded world; a firebug chases you, swings and
throws ember bolts; you fight back with a sword you picked up or a spell you composed in the spellmaker;
a campfire hums where it is standing; you save, quit, load, and it is all still true a hundred sectors
from the origin.

**It is not production ready**, and [`readiness-2026-09-24.md`](readiness-2026-09-24.md) is the honest
account of why — read it before promising anything. The short version: no asset pipeline for real
content, no editor worth the name, no level geometry, no animation beyond sprites, and a renderer that
is one material system and four passes.

## 3. How to build, test and verify

```bash
dotnet build -c Debug && dotnet build -c Development && dotnet build -c Shipping   # all three must build
dotnet test tests/Sage.Tests -c Development       # 405 tests, ~18 s
python games/Sandbox/tools/make_placeholder_art.py    # regenerates the placeholder sprites
python games/Sandbox/tools/make_placeholder_audio.py  # and the placeholder sounds
```

**The suite is for Debug and Development only.** Shipping must *build* and *run*, but
`dotnet test -c Shipping` fails six tests on purpose: they assert behaviour Shipping deliberately
compiles out — `Log.Trace`/`Log.Debug` existing, `Assert.Dev` throwing on a missing component, the phase
contracts reporting a late write, the profiler recording phases, and `DevOnly` cvars being registered.
One of them says so in its own assertion message. It looks like a broken engine and is not one; if you
ever want them green everywhere they need a Shipping-aware skip, and nobody has decided that is worth
doing.

Run the game, scripted, and read what it did:

```bash
./src/Sage.Host/bin/Development/net8.0/Sage.Host.exe -game games/Sandbox \
  +sv_cheats 1 +log_file_level Trace +log_level audio trace \
  +ent_spawn sword_pickup +wait 0.6 +in_tap Use +wait 0.3 \
  +equip practice_sword +wait 0.3 +in_tap Attack +wait 0.5 \
  +snd_stats +screenshot +quit 1
```

- `+<cvar> <value>` and `+<command> <args>` run in order after `config.cfg`; `wait <seconds>` defers the
  rest of the queue; `quit <seconds>` ends the run, so a check never needs a human.
- `in_tap` / `in_hold` / `in_look` / `in_axis` / `in_type` inject input, which is the only way to test
  anything that needs a key press.
- Cheat-flagged commands (`snd_play`, `equip`, `ent_spawn`, `warp`, `give`…) need `+sv_cheats 1` first,
  and say so when they refuse.
- Logs land in `user/sandbox/logs/`, screenshots in `user/sandbox/screenshots/` — and a screenshot can
  be read back and looked at, which is how the origin-rebase camera bug was caught.
- **`+log_file_level Trace` is not optional** in that line. Without it the file sink keeps whatever
  `config.cfg` last saved (`Debug` here), `log_level audio trace` appears to work, and not one trace line
  reaches disk. This paragraph exists because the line above was written without it and printed nothing.

### The verification loop that catches what tests cannot

Everything client-side — the renderer, the UI, audio — is **invisible to the headless tests by
construction**, because the tests have no device. This engine has shipped that bug twice: audio readers
on the wrong event queue (the game fought in silence while every test passed) and a sound record with no
code path. So for anything client-side:

1. Turn the subsystem's log category up (`+log_level audio trace`, `+log_level assets debug`, …).
2. Drive it with `in_tap`/`+command` and `wait`.
3. Read the log and assert against what it *says happened*, not what should have.
4. Then write the headless test for whatever part of it *is* a decision, and move that decision into
   `Sage.Engine` if it is not there already.

Step 4 is the whole architectural pattern: `AudioMixer`/`IAudioBackend`, `Panel`/`PanelView`,
`Screen`/`ScreenSystem`, `RenderSnapshot`/`Renderer`. The decision is engine-side and tested; the device
is client-side and decides nothing.

## 5. Sharp edges this engine has already sprung

Each of these cost a debugging session at least once. They are in the code comments too, but this is the
list.

- **An event belongs to the queue of the schedule that *sent* it.** Gameplay sends from `Schedule.Fixed`;
  a Frame-phase system that registers a `Frame` reader finds an empty queue for ever, silently. This is
  what made the first audio system play nothing while every test passed.
- **An event must carry what its reader needs.** `world.Destroy` is immediate, and every reader is later
  than the sender, so an event that names an entity may describe a corpse. `Used` carries the item and
  the point for exactly this reason (04 §3.2).
- **A cue names a moment as well as a reaction.** An ability has `castCues` *and* `cues`; one list raised
  at both the launch and the landing puts the burst in the caster's hand.
- **A bare record id inside a `patch` resolves in the *patched* record's namespace**, not the file's. A
  game patching `sage:physical` with `"sound": "hit_flesh"` points at `sage:hit_flesh`, which does not
  exist. Write ids in full inside a patch until R11 fixes it. Validation does catch it, loudly.
- **`EqualityComparer<T>.Default` boxes** a struct that does not implement `IEquatable<T>`, and
  **`Enum.HasFlag` boxes** its argument. Both showed up as kilobytes per tick in R18's scale test and
  neither was visible to any correctness test. `scale_report` measures the **Fixed** schedule only —
  Frame-phase allocation is not covered by anything yet.
- **Everything that holds a position must subscribe to a rebase** (`world.Origin().Rebased`): physics,
  the renderer, the audio mixer, debug shapes with a duration, the editor camera. Scene coordinates and
  saves are **origin-space**, so a save carries the sector it was written in.
- **`log_file_level` in `user/sandbox/config.cfg` caps the log file.** If it is `Debug`, no `TRACE` line
  reaches disk no matter what `log_level` says, and you will conclude your logging is broken. It is an
  `Archive` cvar, so whatever you set with `+log_file_level` is saved for next time.
- **Daggerfall's art is Bethesda's.** `games/Sandbox/content/data/daggerfall.json` and
  `content/textures/daggerfall/` are gitignored and the importer reads the user's own install. Never
  commit any of it. The placeholders are *generated* by the two Python scripts for the same reason.
- **A press is not whatever a device says.** Input is ignored entirely while the window is not focused,
  edges come from the raw device state rather than the consumed one, and a trigger bound to a button has
  hysteresis (08 §3.7, review #60). If you add a device or an action kind, those three rules are in
  `Sage.Engine/Input/InputGating.cs` and are the reason the player no longer swings at nothing.
- **`SpriteBatch.DrawString` throws on a glyph the font lacks.** `ui.spritefont` has explicit character
  regions and a `DefaultCharacter`; widen the regions rather than trusting input.

## 6. Known leftovers, by subsystem

| Subsystem | Left undone |
|---|---|
| Audio (11) | Music and crossfades, OGG (needs a decoder), reverb and occlusion, footsteps from animation events, an attack overriding its damage type's hit sound, screens making any noise, effect records raising cues (11 §13) |
| Records (05, R11) | Per-field namespaces at merge (the patch sharp edge above), generated readers and validators, range checks, `RecordRef<T>` |
| Rendering (06) | Point lights beyond the nearest few, lightmaps, HDR, anything resembling an asset pipeline |
| Animation (12) | Skeletal animation and glTF; sprite frame events exist but only `hit` is consumed |
| UI (13) | Screens are lists and fields; no layout engine beyond `PanelLayout`, no controller navigation, no sound |
| Editor (15) | Barely started: ImGui dev tools, no documents, no command log, no level geometry (F16) |
| AI (16) | A navmesh for brush-built interiors (F23's later half), a coarse graph for crossing sectors, doors as path links, crowds that avoid each other, and hearing (perception is sight only) |
| Input (08) | `bind`/`unbind` and a user input map; the editor camera still reads devices directly |

## 7. House rules

- **Commits:** never add a `Co-Authored-By: Claude` trailer. Mention Claude as plain text in the body
  instead, e.g. `Written with Claude Code (Claude Opus 5).` Commit messages here are prose that explains
  *why*, in the same voice as the code comments.
- **After every change, do a second pass** before reporting it done: re-read the diff looking for gaps
  and inconsistencies, not for typos. Every second pass in this session found something real, and three
  of the five F4 findings were things no test could have caught.
- **Assessments go in the docs**, not in chat: a dated write-up in `docs/history/`, R/F items in
  `TODO.md`, and a pointer in the relevant `docs/design/NN-*.md`. **Verify every count against the code
  before writing it** (`grep -rhoE '\[Record\("[a-z_]+"' --include=*.cs src/ games/ | sort -u | wc -l`,
  and so on) — a number in a doc that the code disagrees with is worse than no number.
- **Prove a test is not vacuous.** Reintroduce the bug, watch the test fail, then put it back. This is
  how the cue-timing test, the streaming margin and the rebase subscription were all confirmed.
- **Zero allocation in the steady state** (02 §4.6). It is measured, and the measurement is cheap to run.
