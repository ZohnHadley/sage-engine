# Plan: research-backed architecture revision + subsystem design docs

> **Status:** approved 2026-09-22, then **revised after approval** (same day) so that it matches the final design docs. The seven revisions are listed in "Revisions after approval" below and marked *(revised)* where they appear. `docs/design/*` is authoritative; this plan records how the design was reached.

## Context
The user wants the engine plan grounded in how real engines are structured and *why*, and then detailed down to the subsystem level: how assets load, shaders, rendering, events, dev-mode logging, and so on. Three research passes covered:
- **classic engines:** Quake 1–3, GoldSrc, Source, Unreal 1–3, Bethesda Gamebryo/Creation, the Warband module system, Lugaru;
- **modern engines:** UE5, Unity/DOTS, Godot 4, Bevy, O3DE, Stride, Flax, Bitsquid, Our Machinery, Frostbite, Naughty Dog, Destiny, Overwatch, idTech 7, and Gregory's *Game Engine Architecture*;
- **cross-cutting patterns:** game loop, entity models, netcode, large worlds, assets, reflection, modules, C# library status, why hobby engines fail.

The user's decisions:
- **Multiplayer later, not now.** Don't build netcode; follow cheap "readiness rules" so adding it later isn't a rewrite.
- **Daggerfall-like first.**
- **Modding = data + trusted C# mods.**

The current `ARCHITECTURE.md` treats networking as built in from day one. It gets downgraded to a later phase, the research gets folded in with reasons and sources, and each subsystem gets its own design doc.

This is documentation only. No engine code changes.

## Second-pass review (applied throughout this plan)
| # | Issue in the first draft | Revision | Why |
|---|---|---|---|
| 1 | "Every module is a csproj" (module system) contradicted ARCHITECTURE §9's "start with few assemblies" | **Two levels:** csproj boundaries only at *layer* boundaries (Engine-sim, Client, Framework, Editor, Host, Game). An `IModule` is a *logical* unit inside an assembly (Renderer, Physics, Audio…), with declared dependencies and init order | Build-enforced where it matters (sim ↛ MonoGame, runtime ↛ editor) without 20 projects for a solo dev |
| 2 | Godot-style "servers" could be read as building command-queue servers | Reworded to **"subsystems own their data; components hold handles"**. Physics = Bepu's own `BodyHandle` storage; render = GPU resources by handle; no custom command queues | Same benefit (decoupled, thread-ready) with far less machinery |
| 3 | The `World` facade over the "Friflo spike vs our own" choice pre-committed to our own generational ids and our own serializer, which Friflo partly provides (ids, hierarchy, JSON) | The ECS doc states **requirements** (stale-handle detection, stable `PersistentId`, `EntityRef`, command buffers, hierarchy, serialization hooks). The spike picks the implementation. The facade stays thin: world lifetime, ids, spawning. It doesn't wrap every query, or the library's performance is lost | Avoids double work and a leaky abstraction |
| 4 | Bevy-style double-buffered events are known to miss or double-read across fixed vs frame schedules | Events are **per schedule**, and each reader has its own **cursor** (Bevy `EventReader`), so nothing is read twice or dropped. Fixed-tick events are for fixed systems; frame-side readers use their own cursor | Fixes a real, documented pitfall |
| 5 | Entity I/O with runtime-resolved strings is untyped (a known Source pain) | Names are **resolved to `EntityRef` at map load**. Inputs are **validated against generated component metadata**, so the editor offers only valid inputs and load errors are logged with the map location | Keeps the flexibility, loses the silent typos |
| 6 | Shader permutations via a define matrix + a custom compiled-effect cache | Use **MonoGame effect techniques** as permutations (a small, named set generated by macros in the `.fx`), selected per material. No custom cache | Idiomatic MonoGame; no combinatorial explosion; one `.mgfxo` per shader |
| 7 | Materials, input maps, items and spells each had their own file format | **One data-record pipeline** (JSON records, namespaced ids, load-order merge, schema validation, hot reload) for *all* definitions, including materials and input action maps. Prefabs and maps use the entity serializer | One loader, one merge rule, one validator, one hot-reload path |
| 8 | Fixed tick given as 64 Hz here and 60 Hz in the existing docs | **60 Hz**, set by the cvar `sim_tickrate` | Consistency; interpolation hides the difference either way |
| 9 | `RenderSnapshot` could allocate every frame | Snapshot buffers are **pooled and reused** (arrays grow and never shrink during play) | GC rule from ARCHITECTURE §4.4.1 |
| 10 | Instancing needs MonoGame's HiDef profile, which the plan didn't mention | Require `GraphicsProfile.HiDef`. It's verified while writing. *(revised, A: instancing moved to later; HiDef still set)* | Otherwise `DrawInstancedPrimitives` isn't available |
| 11 | A pipelined render thread "later" ignored MonoGame's main-thread-only `GraphicsDevice` | Noted: pipelining means **simulation on a worker thread and rendering on the main thread**, with Extract as the hand-off | Keeps the future option realistic |
| 12 | Asset identity by virtual path vs GUID was left open | **Path now** (mod shadowing needs it); the editor has a rename/refactor command. If renames hurt, add **Godot-4-style `.uid` sidecars** later that resolve to paths | Godot moved to uid files over rename pain; path-first keeps modding simple |
| 13 | 18 docs risk speculative over-design and rot | Every doc gets a **"v1 scope"** section (the minimum for the Daggerfall-like vertical slice) separate from "later". Short docs stay short until their phase starts | Matches the "write games, not engines" strategy |
| 14 | **Dev-mode logging missing** (the user flagged this) | Core services + logging is promoted to a **detailed doc (`02`)**. Build configurations are defined (**Debug / Development / Shipping**, as UE does) plus the console + a `developer` cvar; *(revised, G: no separate runtime dev mode)* | The user asked for it; logging underpins every other subsystem's debug hooks |
| 15 | The asset-scope and ref-count story was muddled | A **scope is a bag of refs**: loading "into" a world or level scope takes refs, and unloading the scope releases them. Refcount-to-zero → LRU → evict | One mechanism, not two |

## Revisions after approval (2026-09-22)
Found while writing and checking the design docs, then folded back into this plan:

| # | Approved plan said | Final design | Why |
|---|---|---|---|
| A | Instancing (`DrawInstancedPrimitives`) as the main batching path in v1 | **v1: CPU-batched sprites** in a dynamic vertex buffer + loop batching for meshes; instancing **later**, behind `r_instancing`, after testing on target GPUs | MonoGame's GL instancing needs OpenGL 3.2+ and has bug reports; CPU batching works on every driver and is enough for atlased sprites |
| B | Sprite technique `Billboard` | Sprite techniques **`Unlit`, `Lit`, `UnlitBlend`** in `sprite.fx`; quads oriented by the CPU batcher (later: an `Instanced` technique) | Billboarding is a vertex-generation concern, not a shading variant |
| C | MGCB kept "only for `.fx`" | **MGCB not used at all**; `.fx` compiled by `dotnet-mgfxc` from an MSBuild target | Simpler, scriptable for shader hot reload, one less toolchain |
| D | Boot: `Init` modules → subsystems → game module `Register` | Modules **`Init` = register only** (schemas, loaders, systems, cvars) → **records loaded and validated** → graphics → modules **`Start`** (use records/GPU) → world | Records can't be validated before their schemas are registered |
| E | "previous/current transforms for interpolation" (form unspecified) | **`GlobalTransform` stores poses** (position/rotation/scale); matrices built at Extract | Lerping matrices distorts rotations; poses lerp/slerp correctly |
| F | Sprite sheet = client asset | **`.sheet.json` (`SpriteSheetData`) is a simulation-side asset**; the texture stays client-side | Animation time and frame events (melee "hit" frames) belong to the simulation |
| G | Runtime `-dev` flag / "dev mode" | **No separate dev mode.** Build configurations decide what exists; the console + cvars switch features; `developer` is a `DevOnly` cvar that only sets defaults; `DevOnly` = compiled into dev builds only; Shipping keeps a restricted console (`con_enable`, cheats behind `sv_cheats`) | The user asked whether the console is enough: it is, except for compile-time stripping. Removes a redundant concept (01 §3.2) |

Also clarified while writing (not changes of direction): `Look` is applied before each frame's ticks (no frame of lag, 08 §3.4); framework client code lives in `Sage.Framework.Client` (01 §3.1).

**Detailed docs**

**`00-index.md`**: reading order, one line per doc, the template, and the glossary of shared names (`World`, `EntityRef`, `AssetRef<T>`, `RenderSnapshot`, `PlayerCommand`, phase names, log categories).

**`01-host-and-modules.md`**
- **Boot sequence:**
  1. Parse args (`-game <dir>`, `+cvar value`, `+command args`).
  2. Core services (logging first, then cvars from `config.cfg`).
  3. VFS mounts (engine → framework → `game.json` mounts → mods).
  4. Modules: load assemblies, dependency sort, `Init` in order (**register only**) *(revised, D)*.
  5. Records: load, merge, validate against the registered schemas.
  6. Graphics device, then modules `Start` in order.
  7. World creation, then the loop.
  8. Shutdown in reverse, flushing logs last.
- **Module system:** two levels (review #1): `IModule`, module kinds (Runtime / Editor / Tool) and `DefaultModules`.
- **Main loop:** `IsFixedTimeStep = false`, our own accumulator with a clamped frame time (Fiedler), render interpolation alpha, 60 Hz `sim_tickrate`.
- **Build configurations** and console availability: dev builds vs Shipping; `developer` as a defaults setter; `DevOnly` compiled into dev builds only; restricted Shipping console *(revised, G)*.
- **Current code:** `Game1` → host; `Program.cs`; `EditorManager` split.

**`02-core-services-and-logging.md`** (new detailed doc, per the user)
- **Logging API:** `Log.Trace/Debug/Info/Warn/Error/Fatal(category, …)`, with categories as static objects (`LogCat.Render`, `LogCat.Assets`, `LogCat.AI`… plus game-defined ones), like UE log categories / Source spew groups.
  - Per-category verbosity via cvars (`log_level assets debug`) and the console command `log_list`.
- **Zero cost when off:**
  - `[Conditional("SAGE_DEV")]` strips Trace/Debug from Shipping builds entirely.
  - A custom `InterpolatedStringHandler` means disabled levels never format or allocate (GC rule).
- **Context on each entry:** timestamp, frame + tick number, thread, category, level. Optional structured key/values.
- **Sinks:**
  - in-game console;
  - rotating per-session file `logs/sage-<date>-<time>.log` (keep the last N);
  - stdout/debugger output;
  - an editor log panel with filter/search.
  - Sinks are pluggable.
- **Threading:** a lock-free multi-producer queue, with a background writer thread for file IO; the console sink drains on the main thread.
- **Spam control:** `LogOnce`, `LogEvery(seconds)`, and duplicate-collapse ("×120") for per-frame messages.
- **Asserts:** `Assert.Dev(cond, msg)` (conditional). In dev, break into the debugger if one is attached, otherwise log with a stack trace. `Ensure` (logs once, continues) vs `Check` (fatal), as in UE.
- **Crash handling:** an unhandled-exception hook writes a crash report containing:
  - the exception;
  - the last N log lines from an in-memory ring buffer;
  - the cvars;
  - the loaded modules and mods;
  - the build config.

  Then logs are flushed.
- **Later: visual logger** (UE Visual Logger idea). Log entries with world-space shapes, recorded per tick and scrubbable. Valuable for AI.
- **Also covered in this doc:** cvars/console commands (flags `Cheat`, `Archive`, `DevOnly`; later `Replicated`), time/clock, profiler scopes + overlay, the job layer, and GC/allocation rules with per-frame allocation tracking.
- **Current code:** replaces the `Console.WriteLine` calls in `Entity.addComponent` and `EntityContext.getAllEntitiesFromListOfGroups`.

**`03-world-and-ecs.md`**
- Requirements-based storage decision (review #3) + a thin `World` facade.
- `EntityRef`, `PersistentId`, command buffers, hierarchy (`Parent`/`Children` + transform propagation; this makes `TransformSystem` real, #35), previous/current **poses** in `GlobalTransform` for interpolation *(revised, E)*.
- Tags vs bool fields; schedules and system sets with read/write declarations.
- **Current code:** `EntityContext`, `Entity`, `EntityContextListener`, `ArchetypeView`, `ComponentTransform`.

**`04-events-and-messaging.md`**: four mechanisms with distinct jobs, and rules for when to use which. Includes reader cursors (review #4) and typed, load-resolved I/O (review #5).
1. **Structural ECS notifications:** immediate internally, queued for gameplay.
2. **Gameplay event bus:** typed struct events, per-schedule, reader cursors, allocation-free, no re-entrant callbacks.
3. **Entity I/O:** delayed outputs → validated inputs in the EntityIO phase.
4. **Engine signals:** plain C# events for rare callbacks.
- Every mechanism can log its traffic under a category in dev (`log_level events trace`).
- **Current code:** `EntityContext` events, `InputSystem` events.

**`05-assets-and-vfs.md`**
- **VFS:** engine → framework → game → mods (load-order file); loose folders + zip `.pak`.
- **Identity:** virtual path, with `.uid` sidecars possible later (review #12).
- **Handles:** `AssetRef<T>`; an `AssetServer` with an `IAssetLoader<T>` registry; states; error placeholders.
- **Loading:** async decode on workers, GPU upload budgeted on the main thread, scopes as bags of refs (review #15).
- **Hot reload:** `FileSystemWatcher` → generation bump → `AssetReloaded` signal.
- **Dev vs release:** dev loads source formats; release optionally cooks. **No MGCB**; shaders use `dotnet-mgfxc` *(revised, C)*.
- **Sprite sheet data** (`.sheet.json`) is a simulation-side asset *(revised, F)*.
- **Sim vs client** asset split.
- **Data records:** one pipeline for all definitions, including materials and input maps (review #7). JSON, namespaced ids, per-field merge + list patch ops, schema validation.
- **Logging:** every load, failure (with the mount it came from) and override (which mod shadowed what) is logged under `LogCat.Assets`.
- **Current code:** `UtilAssets`, `Content.mgcb`; fixes #9.

**`06-rendering.md`**
- **Structure:** a render subsystem owning GPU resources by handle; **Extract → pooled `RenderSnapshot`** (review #9); cull, sort (64-bit key), batch, passes.
- **Passes:** opaque → alpha-tested sprites/foliage → sky → transparent → debug → UI.
- **Batching:** v1 CPU-batched sprites (dynamic vertex buffer) + loop batching for meshes; instancing later behind `r_instancing`; `GraphicsProfile.HiDef` set (review #10) *(revised, A)*.
- **Billboards:** 8-direction frame selection at extract; quads oriented by the CPU batcher *(revised, B)*.
- **Lighting:** forward (sun + ambient + nearest N point lights), fog, lightmaps later.
- **Other:** camera-relative rendering, render targets (LDR first), an immediate-mode debug-draw API, render stats.
- **MonoGame constraints:** DesktopGL/MojoShader ≈ SM3, no compute; 3.8.5 backends noted.
- **Current code:** `ModelRendererSystem`, `Game1.Draw`, `DevCamera` matrices.

**`07-materials-and-shaders.md`**
- `.fx` compiled by mgfxc; a `common.fxh` include library.
- **Permutations as techniques** (review #6), from a small named set: `lit.fx` `Default`/`AlphaTest`/`Unlit`, `sprite.fx` `Unlit`/`Lit`/`UnlitBlend`; later `Lightmapped`, `Skinned`, `Instanced`. Fog is a parameter, not a variant *(revised, B)*.
- **Materials are data records** (review #7): shader + technique + params + textures + render state; instances override params.
- **Binding:** per-frame / per-material / per-object parameters, with cached `EffectParameter` lookups.
- **Dev hot reload:** mgfxc → swap; on failure, a magenta error shader, with the compiler output logged under `LogCat.Shaders`.
- Replaces `BasicEffect`.

**`08-input.md`**
- Devices, gamepad.
- **Action maps as data records** (rebindable).
- **Context stack:** Editor > UI > Gameplay, with consumption (so ImGui and gameplay don't both react).
- **Per-tick `PlayerCommand`:** look applied at the frame rate *before* the frame's ticks; actions latched until the next tick.
- Recording for replays.
- **Current code:** `InputSystem`, `KeyboardListener`, `MouseListener`; fixes #37.

**`09-serialization-and-saves.md`**
- **Attribute contract** (`[Component]`, `[Property]`, `[Saved]`, stable field tags).
- **Source generator:** binary, JSON and inspector metadata.
- **Saves:** deltas vs procedural baselines, with no behaviour/script state; schema versions with upgraders.
- Prefabs and maps share the serializer.
- **Interplay with Friflo's serializer** is decided by the spike (review #3).
